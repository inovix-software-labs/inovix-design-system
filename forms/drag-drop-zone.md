## 5. Behavior + interaction rules (keyboard, mouse, touch, dismiss, debounce, drag, long-press, right-click)

- Keyboard: Tab reaches browse; Enter opens picker; Escape cancels drag; arrows not used; focus ring on zone.
- Mouse: drag over highlights --color-brand-soft; drop commits; dragleave restores; right-click native menu.
- Touch: long-press previews; swipe not used; browse action always present as the touch path.
- Dismiss: Escape cancels drag; zone never traps focus.
- Offline: drop queues, marks --color-warning, replays on reconnect.
- Debounce: drop events debounce --duration-fast; async type check shows skeleton zone.

## 7. Sound + haptic behavior per event (or explicit silent decision)

Silent by default. Drop accepted -> --sound-success, rejected -> --sound-error, queue -> --sound-warning. Haptics: --haptic-medium on accept, --haptic-heavy on reject. No sound on hover or drag.

## 12. Accessibility requirements (role, aria, focus, contrast, screen reader, reduced motion, high contrast, forced colors)

Per-part aria mapping:
- zone: role=button, aria-label drop zone, aria-describedby hint
- browse: role=button, accessible name, --touch-target-min
- hint: aria-hidden=false, referenced by describedby
- status: role=status for accept, role=alert for reject

Focus: :focus-visible ring --shadow-focus-glow + 2 units --color-border-focus on zone and browse, never outline:none.
Contrast: AA 4:5:1 label, hint, status both themes; error AA; focus 3:1; accept/reject pair icon + text, never color alone.
