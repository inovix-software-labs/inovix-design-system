## 1. Name + one-line purpose

Name: receipt. Section: data-display. Receipt render: merchant header, line items, payment summary, tax, total, footer note, print-optimized.

## 2. Anatomy (parts, ASCII diagram ok)

```
+-----------------------------------+
| merchant                   date   |
+-----------------------------------+
| line                        price |
+-----------------------------------+
| subtotal tax total                  |
| footer note                      |
+-----------------------------------+
```

- **header**: merchant name + logo slot, --text-lg
- **lines**: line item rows, name + price + qty, --font-mono tabular
- **summary**: subtotal tax total, --text-base --font-mono
- **footer**: note + date, --text-xs --color-text-tertiary

## 5. Behavior + interaction rules (keyboard, mouse, touch, dismiss, debounce, drag, long-press, right-click)

- Keyboard: Tab reaches print action; Enter prints; Escape blurs; focus ring on print.
- Mouse: hover print button washes --color-brand-soft; click prints; drag selects line text; right-click native menu.
- Touch: print button >= --touch-target-min; long-press previews; swipe not used.
- Dismiss: not applicable.
- Offline: cached receipt renders, print queued, replayed on reconnect.
- Debounce: print click debounces --duration-debounce-input; async render shows skeleton lines.

| Breakpoint | What changes | Rule |
| --- | --- | --- |

| tablet (--bp-sm..--bp-lg) | two-column grid, details beside | fluid minmax tokens |

## 11. Do / Do not list

Do: reference tokens; ship all 26 states; keep totals tabular; pair printed state with icon + text; hold 40% expansion; announce print via aria.
Do not: hardcode line height; use color alone for printed; hide the ring; trap focus; autoplay sound; ship without line skeletons; let prices overflow.
Premium treatment: calm raised surface at rest, refined hover as print button wash, tactile print press, crisp ring, graceful disabled after print, loading lines matching final line height with zero shift.

## 12. Accessibility requirements (role, aria, focus, contrast, screen reader, reduced motion, high contrast, forced colors)

Per-part aria mapping:
- receipt: role=region or article, aria-label receipt
- lines: role=list, items role=listitem
- summary: role=rowgroup, name from totals
- print: role=button, accessible name print receipt, --touch-target-min

Focus: :focus-visible ring --shadow-focus-glow + 2 units --color-border-focus on print button, never outline:none.
Contrast: AA 4:5:1 line text, totals both themes; printed --color-success with --color-success-content verified; error AA; focus 3:1; currency pairs never color alone.

## 13. i18n requirements (text expansion, bidi, script, plural, locale format)

- Header, line items, footer: externalized, 40% expansion, ellipsis policy.
- Currency and date per locale token; totals plural-safe.
- Bidi isolate spans; RTL mirrors print button position.

All strings externalized to locale files; zero literals in code. Layouts hold 40% expansion from en without truncation, overlap, or fixed heights. Bidi: Unicode algorithm, isolate spans, no concatenated mixed-direction strings. Scripts: Latin/Cyrillic/Greek first with CJK/Devanagari/Arabic fallback stacks from --font-ui; per-script line-height via --leading-* tokens, never fixed px. Plurals: CLDR categories with count token, never hardcoded suffix. Formats: date, time, number, currency, calendar, first-day-of-week, timezone all per locale token; store UTC, label always shown. RTL: full mirror per section 9. Truncation: ellipsis token policy only, never mid-word, tooltip on truncated. Hyphenation: off unless token enables per locale. Line breaking: CJK/Thai rules, no overflow hidden on text.

## 14. Print behavior

Grayscale readable: totals print bold --font-mono, printed prints word printed, no ring, no shimmer, receipt prints framed.
