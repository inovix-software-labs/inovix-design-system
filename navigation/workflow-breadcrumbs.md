## 1. Name + one-line purpose

Name: workflow-breadcrumbs. Section: navigation. Multi-stage workflow trail with status dots per stage, current stage highlighted, max width --measure-reading.

## 2. Anatomy (parts, ASCII diagram ok)

```
+-----------------------------------------+
| (1) stage a  ---  (2) stage b  ---  (3)   |
+-----------------------------------------+
```

- **container**: trail wrapper, max width --measure-reading
- **stage**: --color-brand active, >= --touch-target-min
- **status dot**: --radius-full, success warning or error
- **label**: --text-xs --color-text-secondary
- **connector**: hairline --color-border between stages

## 5. Behavior + interaction rules (keyboard, mouse, touch, dismiss, debounce, drag, long-press, right-click)

- Keyboard: Tab reaches stages, Enter activates stage, arrows move.
- Mouse: hover stage strengthens dot fill, click activates, no drag.
- Touch: stages >= --touch-target-min, swipe not used.
- Dismiss: not applicable, persistent trail.
- Offline: trail cached, renders instantly.
- Debounce: activate debounce --duration-fast, async status skeleton stages.

## 11. Do / Do not list

Do: reference tokens; label each stage; highlight current stage; announce stage change; hold 40% expansion.
Do not: hardcode stage count; use color alone for current; hide the ring; let trail overflow container; autoplay sound.
Premium treatment: premium dot activation via --color-brand, crisp ring, zero layout shift on activate.

## 12. Accessibility requirements (role, aria, focus, contrast, screen reader, reduced motion, high contrast, forced colors)

Per-part aria mapping:
- container: role=navigation, aria-label workflow
- stage: role=link, aria-current=step when current
- status dot: aria-label status, --radius-full
- label: aria-hidden=false, visual text
- connector: aria-hidden=true, visual only

Focus: :focus-visible ring --shadow-focus-glow + 2 units --color-border-focus on focused stage, never outline:none.
Contrast: AA 4.5:1 stage text both themes; current stage --color-brand verified; focus ring 3:1; --color-text-primary on --color-surface-raised verified.

## 13. i18n requirements (text expansion, bidi, script, plural, locale format)

- Stage labels, status names: externalized, 40% expansion, ellipsis policy, no mid-word break.
- Status names per locale token.
- Bidi isolate spans; RTL mirrors connector edges.

All strings externalized to locale files; zero literals in code. Layouts hold 40% expansion from en without truncation, overlap, or fixed heights. Bidi: Unicode algorithm, isolate spans, no concatenated mixed-direction strings. Scripts: Latin/Cyrillic/Greek first with CJK/Devanagari/Arabic fallback stacks from --font-ui; per-script line-height via --leading-* tokens, never fixed px. Plurals: CLDR categories with count token, never hardcoded suffix. Formats: date, time, number, currency, calendar, first-day-of-week, timezone all per locale token; store UTC, label always shown. RTL: full mirror per section 9. Truncation: ellipsis token policy only, never mid-word, tooltip on truncated. Hyphenation: off unless token enables per locale. Line breaking: CJK/Thai rules, no overflow hidden on text.

## 14. Print behavior

Prints stages and labels as text, status as words, connectors as lines, no ring, no interactive states.

## 15. Skeleton loader spec (if data-driven, plus skeleton for every sub-shape)

## 16. Icon usage (Lucide names only)

- check-circle for done stage, alert-circle for error
- Lucide only, --icon-size-md

Lucide line art only, imported by name, never emoji, never custom raster, never icon font. Size from --icon-size-sm/md/lg/xl; stroke from --icon-stroke-thin/regular/thick; color from --color-text-secondary / state tokens; aria-hidden=true on decorative icons, meaningful icons carry aria-label or visible text. No icon-only control without accessible name. Directional icons mirror in RTL. If no Lucide glyph fits, the design system owns the gap: file a decision-log entry, do not hand-draw.
